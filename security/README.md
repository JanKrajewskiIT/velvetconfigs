# Security controls

Source security runs on PRs, release verification and weekly schedules. It does not install or execute application dependencies. Gitleaks scans PR commit ranges and the complete history on main/manual/scheduled runs, with complete redaction. Semgrep combines local security rules with the official semgrep-rules JavaScript/TypeScript/C# rules at a reviewed immutable commit. ERROR findings and parsing errors block the gate. Rules and source are mounted read-only; the scanner has networking disabled. This does not replace an authorization review. Actionlint and zizmor inspect workflows. Scanners run with read-only repository access and no publication or deployment credentials.

`tools.json` owns binary URLs/checksums and container digests. Review upstream releases before updating it; never download an unpinned executable. Action versions are pinned by SHA and maintained by Dependabot. Scanner crashes, invalid reports and database failures fail the gate. Reports are retained for seven days and never uploaded to third-party dashboards. Findings may still contain internal code or URLs; keep artifacts private.

The SPA image verification and package publication jobs explicitly disable automatic package-manager caching in `actions/setup-node`. They consume the verified runtime context or package archive and do not need to restore npm dependency caches in those delivery jobs.

The shared source workflow reads private presets through the Actions secret `CONFIGS_READ_TOKEN`, a fine-grained token with Contents: read on velvetconfigs. It is distinct from `NPM_READ_TOKEN` and production credentials. Public presets need no extra token. Fork PRs without access must fail visibly rather than silently skip the security gate. Own Configs verification reads its local checkout.

Image checks block all HIGH/CRITICAL CVEs, including vulnerabilities without a fix, all HIGH/CRITICAL metadata misconfigurations and every embedded secret. Image exceptions require an exact image reference, package, installed version, advisory ID, severity, reason and expiry in `image-exceptions.json`; expired exceptions fail even if the finding disappears. Secret matches are never included in uploaded image reports. The existing npm audit policy remains separate because bundled frontend JavaScript is not a reliable npm dependency inventory.

Every package verification emits a CycloneDX dependency SBOM using npm; each final image emits a separate CycloneDX SBOM. Runtime SBOMs do not describe the application's bundled npm dependencies. Publish the archive/image that passed the gates. Cosign keyless signatures bind image digests to the GitHub workflow identity; deployment verifies the exact expected repository/workflow/main identity and GitHub OIDC issuer before starting images. Container registry signatures require registry write access, internet access to Sigstore and Linux x64 on the VPS. Deployment downloads the exact Cosign binary/checksum from `tools.json` into the deploy user's private directory; no server Node installation or root privilege is needed. Set `VPS_HOST_FINGERPRINT` for SSH host verification and prefer a read-only `REGISTRY_READ_TOKEN` for VPS pulls (legacy `GHCR_TOKEN` remains a fallback). Never substitute a tag for the scanned digest during verification.

ZAP baseline runs against the ephemeral SPA image in CI without credentials. Full and OpenAPI scans are manual, restricted to the GitHub Environment `security-testing`, and accept only HTTPS URLs on the exact `DAST_HOST` repository variable. Set that host to an isolated staging deployment, never production. Configure environment approval in GitHub. The API scan requires a JSON OpenAPI 3 `DAST_OPENAPI_URL` on `DAST_API_HOST` (defaults to `DAST_HOST`); redirects, external references and off-host server URLs are rejected before scanning. Use low-privilege accounts and disposable data for authenticated tests; the supplied scan is unauthenticated and does not cover logged-in routes. Active scans may mutate data. ZAP reports can contain request URLs; avoid secrets in query strings and use restricted artifact access. The versioned alert policy promotes selected baseline alerts to failures; active scans fail on warnings as well as failures.

WAF deployment routes Traefik through the official ModSecurity/OWASP CRS image before the SPA and Recron gateway. It starts in `DetectionOnly`; set the GitHub Environment variable `WAF_MODE=On` after reviewing false positives and testing OIDC redirects, CRUD, uploads and large payloads on staging. `Off` is deliberately rejected. It does not protect the separately deployed Keycloak service; configure that service at its owning proxy. Audit logs omit bodies and headers, but rule diagnostics may still contain request values: collect restricted logs, redact at ingestion and define retention. Avoid logging cookies, authorization headers or response bodies. WAF checks in SPA CI run in blocking mode and assert that a benign request succeeds and a sample SQL-injection payload is rejected. This is a regression probe, not a penetration test.

Repository settings must be applied in GitHub: protect main and release tags, require the verify and security checks, require review for workflow/security/deployment changes, disallow force pushes, enable Dependabot alerts and secret push protection where available, and protect production/security-testing environments. CodeQL and native SARIF dashboards on private repositories depend on GitHub Code Security; the checked-in scanners do not require that subscription. GitHub artifact attestations on private repositories depend on Enterprise Cloud. npm provenance/trusted publishing is registry-specific; these packages use GitHub Packages, so use explicit Cosign blob attestations/signatures rather than assuming npmjs.com features are available.

Use OWASP ASVS as the application acceptance baseline. Manually verify role and ownership isolation, expired/replayed tokens, logout and refresh, redirect allowlists, upload limits, CSP, valid TLS and health endpoints. Security scanners cannot prove these properties. Periodic jobs re-scan the published images and dependency lockfiles because advisory databases change after release. Knip reports unused files, exports and dependencies separately from security; library entry points preserve the published API.

## Deployment prerequisites

Publish the unchanged Configs 3.5.0 package and v3.5.0 workflow tag first, then refresh consumer lockfiles. After publication, replace shared-workflow release refs with that release commit SHA; third-party actions already use verified SHA pins. Protect both the tag and the workflow/security CODEOWNERS paths. Main/PR verification requires the nested security job, so findings cannot be bypassed by publishing directly through the provided workflows.

The common WAF service is in `security/waf.compose.yml` and is copied into the signed-deployment artifact. Consumer Compose files extend that same preset instead of duplicating rules. Download/copy that file next to the Compose file for a manual deployment. Recron overlays reset Aspire host-port mappings with `!reset []`; use Docker Compose 2.24.4 or newer. The overlay also replaces application image references with the required signed digest variables and removes application build definitions. Only Traefik-facing WAF/docs services join the external proxy network; APIs have no host-published ports. The gateway uses an IP rate limit of 50 requests/second with a burst of 100. Review that limit if an upstream CDN hides client addresses. WAF request bodies are capped at 16 MiB, with a configurable `WAF_JSON_BODY_LIMIT` defaulting to 1 MiB for non-file payloads. SPA roots are read-only, with only `/tmp` writable and all Linux capabilities dropped.

NuGet restore in Recron CI and the periodic security workflow audits transitive packages and blocks NU1903/NU1904 high/critical advisories. Container scans then cover the deployed .NET runtime and discovered application packages. Weekly image scans require the first successful publication of the corresponding latest tags; missing images deliberately fail. Keycloak and the external Traefik deployment are owned elsewhere and need their own scanning/update policy.

Detached package signature bundles are retained for 90 days. Archive them with the release permanently. Keyless Sigstore uses a public transparency log: certificate/workflow identity and artifact digests are recorded publicly, even for a private source repository. Keep code, SBOM reports and operational credentials out of signing annotations. A signature proves signer identity and artifact integrity, not absence of vulnerabilities or a SLSA certification.

## Checks after refreshing dependencies

When the workflow gate fails, the log includes the scanner process exit code and a bounded list of Zizmor High rule IDs and workflow lines. Source excerpts and scanner stderr remain in the restricted `security-workflows` artifact: inspect both `zizmor.json` and `zizmor.json.stderr.log`. Zizmor exit code 14 indicates High findings; codes 1–3 indicate audit, argument or input-collection failures. A Docker launch failure can have a different code, so use the stderr artifact to identify the failing layer. The gate remains blocking in every case.

Run `npm run verify` in each frontend project. On Linux with Node 26, inspect a source gate with `node scripts/security-tools.mjs actionlint gitleaks trivy`, then `node scripts/scan-source.mjs workflows /absolute/repository /absolute/reports`. Full SAST additionally needs the pinned semgrep-rules checkout and Docker. For a prepared SPA context, run `node .deployment/spa/scripts/security-tools.mjs trivy`, `node .deployment/spa/scripts/scan-image.mjs velvet-spa:verified reports/image` and `node .deployment/spa/scripts/verify-spa-security.mjs velvet-spa:verified reports/dast`. Image and DAST checks start containers; run them in CI or the intended test environment. These checks were added to the pipeline and are not evidence that the unpublished ecosystem has already passed them.
